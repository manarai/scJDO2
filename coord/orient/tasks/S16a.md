## Runs (`scripts/s16a_baselines.py`; one dataset × method per detached, timed command)

* **dynamo:** one-shot labelling velocity (as its hematopoiesis tutorial)
  and, separately, scVelo dynamical velocity (S03 settings); SparseVFC in
  PCA-30; `vf.jacobian` per cell → store per-cell Jacobians (PCA basis),
  fixed points and their classes.
* **spliceJAC:** Leiden clusters (resolution 1.0) on the expression PCA;
  `estimate_jacobian` per cluster (default regression); store per-cluster
  Jacobians, eigenvalues, the positive-eigenvalue fraction, transition genes.
* **CellRank:** RealTimeKernel (moscot if installable in `.venv-baselines`,
  else stop and ask) on sampling days, plus a ConnectivityKernel combination
  as documented; GPCCA macrostates, terminal states, fate probabilities.
* **scJDO v1 (amended 2026-10-21):** the published-preprint baseline (v56),
  so that v2 can be compared with the authors' own previous method.
  * **Runner:** new `scripts/s16a_v1.py` — a thin wrapper that loads one
    synthetic dataset and calls `compare/run_v1.py`'s core
    (`_run_fit_drift`: `prepare_trajectory` → `fit_drift` with
    `n_epochs=5000`, `archetype_method="snmf"`, `seed=0` — run_v1's defaults)
    in the `.venv-v1` environment; v1's own default preprocessing and
    representation (v56 Methods: log-normalise, 2 000 HVGs, FA-30). Do not
    edit `compare/run_v1.py`.
  * **Pseudotime:** Palantir strict mode, root r0 of S10's rule (earliest day,
    `default_rng(1000 + seed).choice(day-2 cells, 5)`, first). For
    `v3_transition_s2` and `v3_default_s2` read it from S10's output
    (read-only): `~/Documents/scJDO2-manus/benchmarks/synthetic_multimodal/data/s10/<dataset>/palantir.npz`,
    key `day2_strict_r0` (cell order in key `names`). For `v3_transition_s3`,
    `s4` and `v3_default_s3` (no S10 run) compute it in your folder with
    S03's Palantir settings, strict mode, the same root rule; record roots.
  * Give v1 that pseudotime as its ordering. If v1's API cannot take an
    external pseudotime without editing v1, instead let
    `prepare_trajectory` use the same root cell, and report which was done.
* Record runtime, peak memory and every setting.
